# GPT Image 2 灵活尺寸设计

## 目标

让 Lumenverba 图像技能完整支持 `gpt-image-2` 的官方输出尺寸能力，同时保持请求校验明确、默认行为可预测，并以最小代码改动维护脚本、技能文档和命令行的一致性。

官方依据为 [OpenAI Image Generation 文档](https://developers.openai.com/api/docs/guides/image-generation#size-and-quality-options)。文档说明 `gpt-image-2` 接受 `auto` 或满足约束的任意分辨率，并将总像素超过 `2560x1440` 的输出视为实验能力。

## 范围

本次变更包括：

- 仅支持 `gpt-image-2`，移除 `gpt-image-1` 和 `gpt-image-1.5`。
- 将默认输出尺寸从 `1536x1024` 改为 `auto`。
- 接受 `auto` 或符合官方约束的 `WIDTHxHEIGHT`。
- 将质量参数改为官方值 `low`、`medium`、`high`、`auto`，默认使用 `medium`。
- 移除非官方 `standard`，不保留兼容别名。
- 对实验分辨率发出非阻断警告。
- 在技能文档中提供常用分辨率档位。

本次不增加新的 CLI 档位名称，不改变 API 端点、请求重试、结果回执、批处理或图片保存行为，也不发布新版本。

## 参数行为

### 模型

模型白名单只包含 `gpt-image-2`。技能遇到用户指定 `gpt-image-1` 或 `gpt-image-1.5` 时，必须说明不支持且不得发起创建请求。CLI 和程序化请求构建也必须拒绝非 `gpt-image-2` 模型。

### 输出尺寸

未指定 `size` 时发送 `auto`。显式值只接受小写 `auto` 或格式为 `WIDTHxHEIGHT` 的十进制整数，其中分隔符为小写 `x`。

显式分辨率必须同时满足：

- 最长边不超过 `3840px`。
- 两边都是 `16px` 的倍数。
- 长边与短边之比不超过 `3:1`。
- 总像素不少于 `655,360`，且不超过 `8,294,400`。

无效格式或违反任一约束时，在发送网络请求前返回包含失败原因的参数错误。一个尺寸验证函数同时服务 CLI 解析与程序化请求构建，避免两套规则分叉。

`auto` 的实际输出尺寸由模型决定，因此客户端无法在请求前判断是否会进入实验分辨率范围，也不对 `auto` 发出实验警告。

### 实验分辨率

显式尺寸的总像素大于 `3,686,400`（`2560x1440`）时仍允许执行。技能在最终命令执行前向用户说明这是官方标记的实验范围；直接运行 CLI 时，脚本在 `stderr` 输出一次非阻断警告。警告不得改变退出码、结果回执状态或创建请求字段。

### 质量

质量白名单改为 `low`、`medium`、`high`、`auto`，默认使用 `medium`。`standard` 从文档、CLI 和程序化请求构建中删除；传入时按无效参数拒绝，不进行隐式映射。

质量只控制渲染质量、速度和成本，不代表输出分辨率。输出分辨率完全由 `size` 决定。

## 文档分辨率档位

档位只存在于 `SKILL.md`，由技能在生成命令前转换为实际 `--size` 值。CLI 不接受档位名称。

| 档位 | `--size` | 状态 |
| --- | --- | --- |
| 自动 | `auto` | 默认 |
| 标准方图 | `1024x1024` | 常规 |
| 标准横图 | `1536x1024` | 常规 |
| 标准竖图 | `1024x1536` | 常规 |
| 2K 方图 | `2048x2048` | 实验 |
| 2K 横图 | `2048x1152` | 常规 |
| 4K 横图 | `3840x2160` | 实验 |
| 4K 竖图 | `2160x3840` | 实验 |

用户指定其他比例或像素尺寸时，技能可以直接使用符合约束的自定义 `WIDTHxHEIGHT`，无需增加新的档位。

## 最小实现

脚本只做以下结构性变化：

1. 收紧模型和质量常量，更新默认值。
2. 用一个尺寸解析与验证函数替换固定尺寸集合。
3. 将同一个验证函数用于 `argparse` 的 `type` 和请求构建。
4. 在 CLI 发起请求前判断显式尺寸是否属于实验分辨率，并向 `stderr` 输出一次警告。

分辨率档位不进入 Python 代码。尺寸验证不引入第三方依赖，也不改变现有公开函数签名。

## 错误与警告

- 不支持的模型：参数错误，不联网。
- 非官方质量值：参数错误，不联网。
- 尺寸格式错误：参数错误，不联网。
- 尺寸违反硬约束：参数错误并指出具体约束，不联网。
- 显式实验分辨率：警告后继续，创建请求保持单次且不自动重试。
- `auto`：不预判输出尺寸，不发出实验警告。

警告文本不得包含密钥、请求头、响应体或底层网络异常。

## 测试

离线测试覆盖：

- 默认请求使用 `gpt-image-2`、`size=auto` 和 `quality=medium`。
- `auto` 与官方列出的常用尺寸均可通过。
- 边长、16 倍数、比例和总像素的合法边界可通过。
- 每一种硬约束都有至少一个失败用例，且不会进入网络层。
- 大于 `3,686,400` 总像素的显式尺寸产生一次警告但仍构建原样请求。
- `auto` 和常规显式尺寸不产生实验警告。
- `gpt-image-1`、`gpt-image-1.5`、`standard` 和未知值被拒绝。
- `generate`、`edit`、`text`、`batch` 的 CLI 均使用相同尺寸规则。
- README 与 `SKILL.md` 记录模型、默认参数、尺寸约束、实验警告和档位表。

离线门禁通过后，使用已配置的真实 API 进行一次低额度冒烟测试：`gpt-image-2`、`quality=low`、单张图片和一个非旧白名单但处于常规范围的自定义尺寸。创建请求不得在客户端重试，测试过程不得输出或保存 API 密钥。

## 验收标准

- 所有现有测试和新增测试通过。
- CLI 帮助展示 `gpt-image-2` 和官方质量值，并允许 `auto` 或自定义尺寸。
- 自定义尺寸在本地按官方硬约束验证。
- 实验分辨率被明确警告但不阻断。
- 旧模型和 `standard` 在联网前被拒绝。
- 文档档位不增加 Python 代码分支。
- 真实 API 冒烟测试成功，且仓库与输出中不存在密钥。
